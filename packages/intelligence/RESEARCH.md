## Supported shapes and limits

The defaults are 10 MiB uploaded bytes, 2 million text characters, 5,000 messages per conversation, 100 conversations, and 100 PDF pages. ZIP policy permits 100 entries, 20 MiB total expansion, at most 100:1 expansion, no nested archives, and at most six path segments. Callers may lower limits but cannot raise package ceilings. PNG/JPEG/GIF/WebP in a bundle are allowed inert references; arbitrary executables, files, and archive types fail inspection.

UTF-8 text and Markdown recognize explicit User:, Human:, Assistant:, and System: role markers at line boundaries. Fenced code contents never create artificial role boundaries. Unmarked content retains an unknown role. Generic JSON supports messages; Claude-like JSON supports chat_messages with sender and text or text content blocks. Unknown JSON shapes fail with an actionable error. HTML recognizes data-message-author-role or static .message elements; unsupported markup falls back to text with a warning. Source roles and timestamps are only accepted when recoverable, and timestamps without a timezone remain unknown.

## Extraction capability and evaluation

Local extraction is deterministic review assistance. It detects known board-family mentions, common component mentions including stated quantities/resistance, explicit wiring lines, negative requirements, and fenced firmware. It proposes supersession only for explicit GPIO corrections to the same named terminal. Ambiguous assignments and multiple board identities remain conflicts. A mention never means catalog verification. It does not promise general language understanding, dependency resolution, every circuit family, electrical validation, or complete final-design reconstruction.

Production uses the separately configured provider adapter when approved. The endpoint is an administrator-controlled HTTPS URL, redirects are refused, credentials stay server-side, imported data is isolated from instructions, and no model tools or source-selected URLs are available. Input and response budgets fail closed; provider failures never silently downgrade to local output. Protocol compatibility still requires a selected provider/model integration check. No real customer conversation is sent in tests. Provider retention, regional routing, cost ceilings, and operator policy remain release prerequisites.

Twenty-eight synthetic conversation fixtures evaluate known rule capabilities: quantities, stated/unknown resistance, board variants, explicit and ambiguous correction, multiple boards, firmware changes, polarity, negative instruction, missing wiring, role injection, and Unicode evidence/units. The benchmark uses complete expected candidate sets per fixture, reports false positives and false negatives by kind, checks final connection decision states and explicit supersession edges, and validates exact provenance. These fixtures establish regression behavior for this supported scope. They do not measure recall over arbitrary user conversations. A broader labeled corpus and model-specific benchmark are required before making reliability claims.

Candidates include discriminated structured details. Board manufacturer/model/revision, component quantities/resistance, and connection endpoints stay null unless explicitly supported by source text. Resistor unit conversion accepts stated Ω/ohm, kilo, mega, milli, and micro values; arbitrary numbers beside a component never become resistance. Literal named fields, explicitly stated numeric quantities/units, source code language/content, and component references are checked before provider results are accepted. These conservative checks may reject paraphrased provider output; the provider prompt therefore requires source wording. A passing source check still does not establish electrical truth.

## Isolation responsibility

Byte and count limits inside a library cannot interrupt a synchronous parser that exhausts CPU. Run this package in a dedicated resource-bounded worker process with no general network egress. Provider extraction should use an approved egress path separately from file parsing. Kill the parser process on its wall-time/memory budget and discard uncommitted output. Never execute imported firmware or render imported source HTML.
